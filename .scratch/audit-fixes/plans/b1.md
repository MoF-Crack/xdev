## 二、逐票实施方案

### 票 01 go.yaml GOROOT v2 + 注册表残留清理（PR-1）

**改动清单**：`manifests/go.yaml`、`internal/env/win_path_windows.go`（或 installer doctor 路径）、`internal/cli/doctor.go`

**实施步骤**：
1. manifests/go.yaml 删除第 12 行 `GOROOT: '{{install}}'`（GOPATH `{{install}}\..\gopath` 不动）。GOPATH 语义：install 根外、工具根内——不受布局影响。
2. internal/env 新增 `CleanupStaleGOROOT() error`（Windows）：
   - 读注册表 GOROOT（`GetUserEnvVar("GOROOT")`）；空则 no-op；
   - 判定 `isGOROOTDir(V)` = `V/pkg/tool` 目录存在（镜像 Go 官方 `findGOROOT` 的 isGOROOT 探测，cmd/go/internal/cfg/cfg.go:634-640）；
   - **删除条件**：`!isGOROOTDir(V) && isGOROOTDir(V+"\\go")`（值错指一层、其嵌套 go/ 才是真 GOROOT）→ 删除该注册表值；
   - 其它情况（值合法 / 嵌套也不存在）不删——未知来源保守保留。
3. 调用点两处：`xdev doctor`（cli/doctor.go）无条件跑；installer 的 Activate 对 tool=="go" 后跑（存量用户 `xdev use go` 自愈）。
4. Unix stub：win_path_other.go 加同名 no-op。

**边界与坑**：
- 不得用「GOROOT 注册表值 != {{install}} 即删」的粗暴规则——用户手动装的多 GOROOT 场景会误删；
- EnrichFromRegistry 会在下次 shim 调用时重新注入——**必须删注册表值本身**（不删值，清环境变量无意义）；
- 删除动作经 SetUserEnvVar 家族的删除 API（保留操作日志）。

**回滚**：manifest 行恢复 + doctor 调用点移除即回滚；注册表删除动作幂等可重放。

### 票 02 sshpass argv + SSH Exec 错误传播（PR-2，含 P1-32/N-05）

**改动清单**：`internal/orchestrator/ssh_adapter.go`、新增 `internal/orchestrator/sshpass_argv_test.go`

**实施步骤**：
1. 新增纯函数（同包）：
   ```go
   // sshPassArgv 构造 sshpass 的完整 argv：-e 从 SSHPASS 环境变量读密码（1.06→1.10 全系支持）。
   // 注意 1.10 的 -e[env_var] 可选参数必须紧贴（-eVAR），不得空格分隔。
   func sshPassArgv(sshBin string, args []string) []string {
       return append([]string{"-e", sshBin}, args...)
   }
   ```
2. `runSSH`（:63）：`full := sshPassArgv(sshBinary(), args...)`；签名改 `runSSH(ctx, args) (stdout, stderr []byte, err error)`——内部 `cmd.Output()` 改手动 `var outBuf, errBuf bytes.Buffer; cmd.Stdout=&outBuf; cmd.Stderr=&errBuf; err := cmd.Run()`（密码路径需要 stderr；sshpass 的 "Failed to run command" 落在 stderr）。调用方 TestConnection 只用 stdout。
3. `ConnectInteractive`（:146）：`c = exec.CommandContext(ctx, "sshpass", sshPassArgv(sshBinary(), args...)...)`。
4. `Exec`（:119-132）重写：
   - 密码路径：`stdout, stderr, err := s.runSSH(...)`；ExitCode 用 `util.ExitCode(err)`（exec.go:18 先例）；返回 `&ExecResult{Stdout, Stderr, ExitCode}` + err **保留传播**；
   - 无密码路径【N-05】：`result, err := util.RunCommand(...)`——err 不再 `_` 丢弃，`return &result, err`。
5. ssh_connect_test.go 的 Skip 逻辑保留；修正文档/注释中的测试名引用（`TestConnectInteractive_PasswordNeverOnArgv`）。

**边界与坑**：禁止任何处手抄 `{"-e", sshBinary(), ...}` 字面量（票 07 与未来改动唯一出口是 sshPassArgv）；stderr 提取后错误信息拼接保持中文提示（密码登录需要 sshpass）不变。

**回滚**：单文件域，revert 即回滚。

### 票 05 RegEnumValueW 健壮性（PR-6）

**改动清单**：`internal/env/win_path_windows.go`（GetAllUserEnvVars :1370-1394 + EnumEnvVars :920-935）

**实施步骤**（GetAllUserEnvVars）：
1. ERROR_MORE_DATA 分支：
   ```go
   if ret == _ERROR_MORE_DATA {
       need := nameBufSize           // API 写回的所需长度
       if need > 16383 { need = 16383 }  // 值名上限 16,383 字符
       nameBuf = make([]uint16, need+1)
       nameBufSize = uint32(need + 1)    // 关键：重置为 buf 实长（lpcchValueName 为 in/out）
       ret, _, _ = procRegEnumValue.Call(...)  // 重试同一 index 一次
       if ret != 0 { log.Printf(...); index++; continue }
   }
   ```
2. 其它非零返回码 `break` 前 `log.Printf("[env] WARN: enum HKCU\\Environment aborted at index %d: ret=%d", ...)`。
3. EnumEnvVars（:920-935）同模式修复（值数据 buf 32768 → MORE_DATA 时按 lpcbData 重分配重试一次 + 日志）。

**边界与坑**：**重试前必须重置 nameBufSize 为新 buf 长度**——沿用 API 写回的 required 值会造成系统性二次失败（buf 已是 required+1，API 仍报 MORE_DATA）→ 长名值被永久跳过；恰 256 字符值名为截断错名（非 panic）——测试用例覆盖。
