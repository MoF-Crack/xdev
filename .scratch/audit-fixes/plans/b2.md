## 二、逐票实施方案

### 票 09 copyDir SkipDir + junction 机制 + 断链可见化（PR-9）

**改动清单**：`internal/util/fs.go`（copyDir 86-105）、`internal/util/fs_test.go`、`internal/gui/app_migration.go`（消费 skipped 计数）

**实施步骤**：
1. **主修复**：:101 `return filepath.SkipDir` → `return nil`。
2. **分支条件扩展**：:86 `info.Mode()&os.ModeSymlink != 0` → `info.Mode()&(os.ModeSymlink|os.ModeIrregular) != 0`。
3. **解析顺序重写**（复核修订机制——EvalSymlinks 对末位 junction 返回自身**而非报错**）：
   ```go
   resolved, err := filepath.EvalSymlinks(path)
   if err != nil || resolved == path {
       // EvalSymlinks 对 junction 返回自身（winsymlink=1）——转 Readlink 兜底
       if target, rerr := os.Readlink(path); rerr == nil && target != path {
           if abs, aerr := filepath.Abs(target); aerr == nil { resolved = abs } else { resolved = target }
       } else {
           // Readlink 也失败：按普通文件处理（维持响亮失败），计入 skipped
           log.Printf("[copydir] WARN: unresolvable link entry %s: %v", path, err)
           skipped++
           return nil
       }
   }
   fi, err := os.Stat(resolved)
   if err != nil {
       log.Printf("[copydir] WARN: broken link entry %s -> %s: %v", path, resolved, err)
       skipped++
       return nil          // 断链条目可见化（N-01）：不再静默
   }
   if fi.IsDir() {
       if resolved == path { return nil } // 自递归护栏（罕见语义歧义）
       if err := copyDir(resolved, target, onProgress); err != nil { return err }
       return nil           // 关键：不返回 SkipDir
   }
   ```
4. **skipped 计数外传**：copyDir 增 `skipped *int` 内部参数；公共 API 增报告版 `CopyDirReport(src, dst string, onProgress func(...)) (files, skipped int, err error)`；`CopyDir/CopyDirProgress` 保持原签名（内部记录 skipped 到 log）。gui/app_migration.go 迁移完成消息显示 `skipped N 个无法解析的链接条目`。
5. Windows junction 测试用 `util.CreateJunction`（fs.go:204，mklink /J 无需管理员）。

**边界与坑**：非 junction 的 ModeIrregular 文件（罕见）由 `os.Stat(resolved) IsDir` 门槛天然排除；`resolved==path` 双护栏（EvalSymlinks 大小写规范化可能返回与输入不同的字符串——用语义等值判定时不可再递归进自身）。

### 票 12 批量会话 dispose + 重入守卫（PR-12）

**改动清单**：`frontend/src/AppContent.vue`、`frontend/src/composables/useParallelBatch.js`、`useBatchUpdates.js`、`DashboardPage.vue`、vitest specs（useParallelBatch.spec.js、useBatchUpdates.spec.js、batchUpdates.integration.spec.js）

**实施步骤**：
1. `createBatchSession`：`const scope = effectScope(); const session = scope.run(() => { const s = useInstall({...}); watch(...)×5; return s; })!;` → `row._scope = scope`。
2. dispose 管道：`run()` 的 `Promise.allSettled` 结果统计完成后逐行 `row._scope?.stop(); row.session?.dispose();`；`clear()` 与 `run()` 开头重置 items 前对旧行同样执行。dispose 幂等（useInstall.js:175 disposed flag 已有）。
3. 重入守卫四层：
   - `installAllUpdates` 入口：`if (batchActive?.value) { message.warning(t('install.busy')); return; }`
   - **批量确认弹窗 onPositiveClick 内二次检查** `if (batchActive?.value) return;` 再置位/启动（堵「弹窗停留期间第二次点击」窗口）；
   - `run()` 开头 `if (items.some(it => it.active)) return { done: 0, failed: 0, cancelled: 0 };`
   - **finally 所有权**：`const owned = !batchActive.value; batchActive.value = true; ... finally { if (owned) { batchActive.value = false; setShowProgress(false); } }`——被拒方不复位运行中批次状态。
4. DashboardPage「全部更新」按钮 `:disabled` 加 `batchInstalling`（经 props/emit 传入）。
5. **测试基建升级**：wails mock 支持 EventsOn 计数器（`window.runtime.EventsOn` 计数 + 卸载钩子）；spec 改用**真实 useInstall 会话**（不再纯 mock sessionFactory）+ `window.go.gui.App` 桩。
