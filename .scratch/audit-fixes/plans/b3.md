## 二、逐票实施方案

### 票 13 签名链完整性 + TOFU 门控（PR-13）

**改动清单**：`internal/downloader/downloader.go`、`internal/installer/installer.go`、`internal/gui/app_install.go`、`internal/installer/installer_test.go`、（守卫）`internal/signer/verify.go`、新测试 `internal/downloader/signature_gate_test.go`

**实施步骤**（按依赖序）：

1. **Options 扩展**（downloader.go）：新增 `Version string`、`OSArch string`、`UnsignedVersion bool`；两个构造方（installer.downloadWithProgress、gui/app_install.go 的 options 组装处）传入。
2. **UnsignedVersion 推导**（两管线各自、同一逻辑）：
   ```go
   allowTOFU := false
   if m := p.Manifest(); m != nil {
       if v, found := m.FindVersion(ver); found {        // 不得丢弃 found（nil panic）
           allowTOFU = v.Discovered || v.Unverified      // 不带哈希条件！
       } else {
           allowTOFU = true                               // 自定义工具/未命中：配合 LoadManifestSignature 的 TOFU 资格
       }
   } else {
       allowTOFU = true                                   // Lua/vfox 插件（nil-Manifest）
   }
   ```
   **GUI 侧自建推导，禁止复用 versionUnverified helper**（:458-473 只查 Unverified 漏 Discovered 且带 npm 特例——复用即两管线判定分叉）。
3. **三处门控接同一标志**：
   - L-10 拒绝分支（:544/:586）：`!opts.UnsignedVersion` 加入条件（哈希空/零检查保留在分支内部）；
   - 签名成员检查（:705-712）：`ms.SHA256Map != "" && !opts.UnsignedVersion && ...` 才执行（重装时 TOFU 写回的真实哈希不在签名图——不门控则误判 tampering）；
   - **逐 URL 过滤**（新逻辑，见步骤 4）同样 `!opts.UnsignedVersion` 才执行。
4. **逐 URL 过滤**：在 Download 组装候选 URL 列表处（downloadWithRetries :352-354 的候选循环）：对每个候选 URL 计算生效哈希（`URLShaMap[url]`，miss 则 ExpectedSHA）→ 精确键检查（步骤 5）→ 未入签的候选剔除并 `OnStatus("mirror hash not covered by signature — skipping")`；主 URL 被剔则顺延首个剩余候选；全部被剔才报错。
5. **verifyManifestSignature 精确键定**：
   - 主路径：`m[opts.Version][opts.OSArch]` 存在且 EqualFold(期望哈希) → 过；
   - **回退（收紧为同版本键域）**：精确键 miss 时，遍历 `m[opts.Version]` 的全部 os/arch 键，任一命中期望哈希即过（老 sig 同版本跨平台兼容）+（mirror URL 场景）URLShaMap 该 URL 值 == 官方 a.SHA256；**全表跨版本回退删除**；
   - 新增：`ms.Tool != 所装工具 → 拒`（N-02 跨工具混淆关闭）；
   - 键格式 `a.OS+"/"+a.Arch` 与签发端（internal/cli/sign_manifest.go:71）一致性单测固化。
6. **third-party / TOFU 同名防线**（installer.go LoadManifestSignature :726-743）：
   - :739 判定前增加：`if 工具名 ∈ 内置 manifest 集合（嵌入 + 磁盘非 third-party 目录）→ isThirdParty = false`（内置签名验证路径；错误信息引导改名）——**嵌入式签名命中后同样不得置 true**（N-03）；
   - TOFU 资格判定（步骤 2 的 else 分支 + LoadManifestSignature 的「全 Discovered manifest」授予逻辑）同样施加同名守卫：与内置同名的磁盘 manifest 不得以「全 Discovered」身份获得 TOFU 资格。
7. **TOFU 写回目录**：installer.go:772 `filepath.Join(i.cfg.Core.XMDevDir, "manifests")` → `i.cfg.Core.ManifestDir`（N-04）。
8. `installer_test.go:840` 唯一 downloadWithProgress 测试调用点同步加参。
9. **manifest.go:374-378 注释更正**（「嵌入优先」实现 vs 注释矛盾——顺带，票 28 主修）。

**边界与坑（实施前必读）**：
- **嵌入优先合并前提**：守卫测试全部按「磁盘**新增版本**条目」场景构造（磁盘篡改内置字段经合并不生效——空洞测试）；
- 占位公钥构建（HasRootKey()=false）签名分支整体跳过 → 全部现行为不变——回归锚点；
- 逐 URL 过滤必须先于主 URL 确定执行，且 opts.URL 同步顺延（downloadSingle :532 按 opts.URL 查 URLShaMap）。
