### 票 23 manifest 文件锁 + sidecar 原子写（PR-19，先行）

**改动清单**：`internal/discovery/scheduler.go`、`internal/manifest/manifest.go`、`internal/downloader/downloader.go`、`internal/util/filelock.go`（如需陈旧锁回收）

**实施步骤**：
1. 盘点 `util.AcquireFileLock`（filelock.go:30）的陈旧锁语义（持有者崩溃后锁文件残留的行为）；若无回收 → 增加 mtime 老化接管（如 >2h 视为陈旧，tryAcquire 时可清除）——**本步结论供票 21 直接复用**。
2. mergeIntoManifest（scheduler.go:722-860）与 UpdateArchiveSHA256（manifest.go:803+）各自 RMW 全程包 `util.AcquireFileLock(filepath.Join(dir, tool+".yaml.lock"), 30s)`；进程内 manifestMu 保留（同进程防重入）。
3. 基线首写点原子化：scheduler.go:740 与 manifest.go:826 的裸 `os.WriteFile` → `util.AtomicWriteFile`；:739-740 的 `_ =` 错误丢弃 → 记日志；scheduler.go:846 的 .bak 写一并原子化。
4. **锁序**：yaml.lock 与 sniff-cache 锁保持串行不嵌套（现流程先 merge 后 updateCacheEntry，保持）；UpdateArchiveSHA256 的 manifestMu→yaml.lock 单向序（manifestMu 为 manifest 包私有，discovery 物理拿不到，无反序可能）。
5. writeSidecarHash（downloader.go:642-654）改五步：`写 <sidecar>.tmp → tmp.Sync() → 目标存在则 Chmod 0644 清只读 → rename → Chmod 0o444`；三个调用点（:564 畸形重写、**:570 全零占位首写**、:609 空 SHA 首写）由函数级修复自动覆盖；自测含 :570 分支。
6. 顺带更正 manifest.go UpdateArchiveSHA256 头注释（自称 atomic write 但首写点裸写——复核发现）。

### 票 21 .part.lock 互斥 + Pause 语义重做（PR-20，单一 PR）

**改动清单**：`internal/downloader/downloader.go`、`internal/downloader/manager.go`

**实施步骤**：
1. **.part.lock 互斥**（P1-01 重设计，替代 v1 的 AllowResume 布尔）：
   - downloadOnce（downloader.go:388 起）进入前 tryAcquire：`partLock, err := util.AcquireFileLock(dest+".part.lock", 1*time.Second)`；拿不到 → 返回明确错误「another download in progress（检测到残留 .part；若确无并发下载请清理缓存重试）」；
   - 拿到 → defer Release（downloadOnce 结束含失败都释放）；O_EXCL 失败→lstat 常规文件→**续传分支保留**（崩溃残留可接管——锁文件随 AcquireFileLock 陈旧回收语义接管，PR-19 第 1 步结论）；
   - downloader.go:405-408 的 symlink 病灶清除重试分支**保留在锁内**（不被「报错」语义吞掉）。
   - GUI StartDownload 与 CLI downloadWithProgress（:667）自动经此机制（Download 单一入口）；Manager.Resume → runDownload → Download 天然满足接管语义。
2. **Pause 语义**（P1-02，与上不可拆）：
   - ① runDownload（manager.go:119）开头 `dlCtx := task.ctx`；`Download(dlCtx, ...)`；收尾判定用 `dlCtx.Err()` 且与当前 `task.ctx` 比对——非当前 ctx → 静默退出不写终态；
   - ② **次序**：Pause（:202-213）在 task.mu 锁内**先** `task.Status = StatusPaused; task.pausedAt = task.Downloaded` **再** `task.cancel()`（v1「cancel 后置位」在窗口内旧 goroutine 读 pausedAt==0 会走 Cancelled 分支删 .part——倒退，必须先置位）；
   - ③ Cancel（:246-277）：`task.cancel` 调用移入 task.mu 锁内（N-06 数据竞争）；os.Remove 失败记日志（Windows 无 FILE_SHARE_DELETE 必 ACCESS_DENIED），依赖 .part.lock 接管语义闭环；
   - ④ CleanupOnExit（:322-339）同改锁内访问 cancel；
   - ⑤ Pause 重复成功问题（N-07）：Pause 改 `if task.Status != StatusDownloading { return error }` 维持 + 由于 ② 立即置 Paused，第二次 Pause 直接被状态门拒绝——pausedAt 不再被覆写。
   - 「立即 Resume 的共写窗口」：docs 注释弱化措辞（旧 goroutine 最后一笔 Write 可落在新 goroutine seek 之后——陈旧块交错，hash 门兜住）。
