# 手动冒烟测试用例（Spec 035 + 036 遗留项）

> 用途：交付桌面环境执行的交互冒烟——覆盖逻辑层单测无法触达的真实 GUI/TUI 链路。
> 配套：单元/组件测试已全绿（go 29 包 / vitest 29 文件 187 用例 / vite build / e2e 18/18）。
> 日期：2026-08-24

## 准备（通用）

1. **二进制已构建好（无需再 build）**：`build\bin\xdev.exe`（16.71 MB，v0.3.3-rc.2，含 Spec 035+036 全部修复，嵌入 pub.key；同目录另有带版本号副本 `xdev-0.3.3-rc.2.exe`）。非交互冒烟已过：`xdev version` → `xdev 0.3.3-rc.2 (built 2026-08-28T22:59:54Z)`、`--help` 正常。
   - GUI：直接双击或 `build\bin\xdev.exe`（零参数）
   - TUI：`build\bin\xdev.exe tui`
2. **保证有 ≥2 个可用更新**（更新列表可能为空时）：先在 Dashboard 点「全部嗅探」或 CLI `build\bin\xdev.exe sniff`；若全部已是最新，用旧版本激活制造缺口：
   - 例：`build\bin\xdev.exe use node@20.18.0`（如已装 22.x）。
3. **保证进度框可见「后台运行」入口**：安装进行时进度框右下有「后台运行」按钮——所有 MS-N2 用例都经它收起对话框后操作界面。

## MS-N2：安装互斥守卫（Spec 036）

> **v2 已修复**：doInstall/repairInstall 静默早退改 busy 提示——所有二级安装入口现统一弹「已有安装进行中」。

### MS-N2a 单装进行中点单项安装入口

| 项 | 内容 |
|---|---|
| 前置 | 任意工具单装进行中（点了 Install → 确认 → 进度框显示「安装中...」） |
| 步骤 | 1. 进度框点「后台运行」→ 对话框收起（安装继续后台跑）<br>2. Dashboard 更新列表点另一项 Install（或工具详情抽屉的 Install）<br>3. 若该项 unverified：会先弹未验证确认框，点「安装」 |
| **期待** | 弹 **「已有安装进行中」** toast（`install.busy`）<br>该项**未静默失败**——无进度框卡死、无假进度<br>后台跑的安装进度状态**不被关掉**（N2 核心修复点） |
| **禁止** | unverified 确认后毫无反应（旧的静默失败）<br>进度框被强制关闭（旧的 `setShowProgress(false)` 误关） |

### MS-N2b 单装进行中点「全部更新」

| 项 | 内容 |
|---|---|
| 前置 | 同 MS-N2a（单装后台运行中） |
| 步骤 | Dashboard 点「全部更新」 |
| **期待** | 弹 **「已有安装进行中」** toast；批量确认对话框**不出现**；批量循环**不启动**（零 installConfirmed 调用） |

### MS-N2c 批量确认对话框等待期间插入单项安装（高级，选做）

| 项 | 内容 |
|---|---|
| 前置 | 批量更新列表含 ≥1 个 unverified 项 |
| 步骤 | 1. 点「全部更新」→ 确认批量<br>2. 出现 unverified 确认框时，**不要立即点**——点「后台运行」收起（若有进度框），再点另一项 Install 并确认<br>3. 回到 unverified 确认框点「安装」 |
| **期待** | 该批量项弹一次「已有安装进行中」（计 failed）<br>剩余项**不逐个撞守卫弹 N 条警告**——批量在下一项预检 `active.value` 让位 break<br>弹 **「批量更新已取消：成功 0，失败 1，跳过 0」**（`install_all_cancelled`，数字按实况） |

## MS-N4：批量更新全流程 + 无闪烁（Spec 036 / 沿用 Spec 035 MS-F2）

> **v2 已修复**：startInstallConfirmed 现返回 started——批量不再在首个项后误中止（成功0 失败1 跳过0 的回归已消除）。

| 项 | 内容 |
|---|---|
| 前置 | Dashboard「可用更新」≥2 项 |
| 步骤 | 1. 点「全部更新」<br>2. 批量确认框点「更新」<br>3. 每项 unverified 确认框逐项弹 → 都点「安装」（要点 N 次，每次一个项）<br>4. 观察进度框逐项推进至结束 |
| **期待** | • **逐项弹确认**（FR-018），非一次性静默跑完<br>• 进度框**逐项推进**：tool A 下载→安装→完成→tool B 开始；**两项之间进度框不闪关再开**（N4 防闪烁——`batchActive` 守卫）<br>• 每项完成弹 **「{tool}@{version} 安装成功」**（`install.success`）<br>• 列表在每项完成后刷新（已装项从列表移除）<br>• 结束弹汇总 **「更新结束：成功 N，失败 M，跳过 K」**（`install_all_summary`，数字真实） |
| **禁止** | 无条件「全部更新完成」假成功（Spec 035 F2 旧 bug）<br>进度框每项关开闪烁（Spec 036 N4 旧症状）<br>跳过的项静默消失无计数 |

## MS-TUI：TUI 更新视图全链路（Spec 035 F3/F4/F5/F9 + Spec 036 N1）

> 终端运行：`build\bin\xdev.exe tui`（或在已 install 的 PATH 上 `xdev tui`）

### MS-TUI-1 键位与视图进入
| 步骤 | 期待 |
|---|---|
| 按 `?` 开 help | 键表含 **`x  Available updates (sniff)`**（F9） |
| 关闭 help，按 `x` | 进入「Available Updates（嗅探结果）」视图，列出可用更新 |

### MS-TUI-2 批量更新 overlay 与 Esc 链路
| 步骤 | 期待 |
|---|---|
| 按 `a` | overlay **替换** updates 视图：显示 `Installing <tool>@<ver>` + **`Batch 1/N`** 行 + 进度条（F4） |
| 安装中按 `a` | 无反应（`installState` 优先，吞键——不会启动第二个批量） |
| 安装中按 `Esc` | **取消当前项并清队列**（F3）→ overlay 消失 → 回到 updates 视图（**不直接退视图**，F4 修复点） |
| 再按 `Esc` | 退出 updates 视图回主视图 |

### MS-TUI-3 负进度无 -1% 泄漏（F5）
| 步骤 | 期待 |
|---|---|
| 启动一个可执行/脚本类（如 rustup）更新项安装 | PhaseInstalling 阶段进度条**保持上次百分比**（如 100%），文案切到「Installing」<br>**不显示 `-1%`、不清零进度条**（F5 修复点） |

### MS-TUI-4 视图内错误提示（Spec 036 N1）
| 项 | 内容 |
|---|---|
| 前置 | 强制一项失败：断网，或 Settings 配置一个无效代理，使下载失败 |
| 步骤 | `xdev tui` → `x` → `a` → 等首项下载失败 |
| **期待** | updates 视图内**直接见 `Error: <失败信息>` 行**（`StyleError` 渲染，无需退回主视图）<br>队列已清（F3）——按 `a` 可重跑 |
| **禁止** | 错误信息只在主视图 errBar（要 Esc 退视图才见）——**N1 旧症状** |
