## 升级步骤

### 从公开 beta.3 / RC1 升级到 RC2

beta.3 / RC1 的 Release 列表更新器可发现 RC2 Pre-release，beta.3 的 Latest 兼容标记继续保留。无修改的公开 RC1 客户端已实际通过公网 ZIP 升级到 RC2。

1. 设置中点击「检查更新」，按原界面选择「下载并安装」；也可退出 GUI 后运行 `xdev self update`。
2. 等待 ZIP 下载、校验、解压与安装完成，再自行关闭并重新打开 XDev。这一轮仍由旧客户端执行，不会出现新版重启按钮。
3. 运行新程序后执行 `xdev version`，确认显示 `1.0.0-rc.2`。新交互从运行新版后生效。

beta.3 尚不读取 GUI 代理设置；受限网络下可使用环境代理或手动下载。较早的 alpha / beta.2 只读取 `/releases/latest`，先经 [beta.3](https://github.com/MoF-Crack/xdev/releases/tag/v1.0.0-beta.3) 升级，或直接手动下载 RC2 EXE。

### 运行新版后的 Windows GUI

1. 点击「检查更新」，界面只展示当前系统、架构对应的更新。
2. 点击「下载更新」。新更新器优先选择对应版本的直接 EXE，仅在该资产完全不存在时兼容 ZIP；EXE 重复、无效或未上传完成时明确报错。
3. 等待 `SHA256SUMS` 与 PE 架构校验完成，界面显示「重启并更新」。此时文件已暂存，原目标未被替换，应用仍运行旧代码。
4. 点击「重启并更新」。助手就绪后 GUI 正常退出；助手等待旧进程退出，再备份、替换并重开，保留 XDev 主目录、工作目录和 `--no-path-fix` 策略。

关闭更新弹窗仍保留已准备的更新；普通关闭整个应用会丢弃尚未交接的暂存文件。启动更新也需要用户确认重启。

- 下载或校验失败：原程序保持不变，可重新下载。
- 助手启动失败：窗口继续运行，保留就绪状态，可直接重试重启，无需重新下载。
- 暂存丢失或内容变化：清除就绪状态，要求重新下载；仅后端返回 `ready: true` 才显示重启按钮。
- 退出后替换或启动失败：助手尝试恢复并重开经过验证的旧程序，重开后显示错误；目标被只读句柄占用时也尝试重开旧程序。无法验证文件身份或目标已变成其他文件时拒绝覆盖。

### 手动升级与 Linux/macOS

从同一 Release 下载平台文件及 `SHA256SUMS`，核对摘要后退出旧应用，再替换可执行文件。Windows 优先使用直接 EXE，ZIP/tar.gz 先解压到单独目录；保留配置目录与已安装工具。Linux/macOS 继续既有 tar.gz 更新及手动重新打开流程，本版的确认重启流程仅适用于 Windows GUI。CLI `self update` 保持直接安装语义。
