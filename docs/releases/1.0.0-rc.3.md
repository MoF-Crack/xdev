# XDev 1.0.0-rc.3

- 软件版本：`1.0.0-rc.3`；Tag：`v1.0.0-rc.3`
- 发布类型：GitHub Pre-release
- 发布方式：GitHub Actions 标签流水线（签名 → 五平台打包 → 汇总校验和 → 签名校验和 → 发布）

RC3 重点处理两件事：一是修正会让商业杀毒软件误判的构建参数，二是给自更新链补上独立于下载通道的真实性校验。

## 杀毒误报修复

发布产物此前带有 `-s`（剥离 PE 符号表）。实测该产物被火绒以 `TrojanDownloader/Agent.cg`（病毒 ID `9E7E8387A8A27F9F`）判定并在写入时直接删除；同一份源码用 `-w`（仅去 DWARF、保留符号表）构建则不被判定。RC3 起发布构建只使用 `-w`。

判定与"未签名""会联网下载""自更新代码"均无因果关系：最小下载器程序、去掉桌面标签的同一份源码、以及注入同样构建变量的产物都不触发。代价是每个平台产物约增大 1.5 MB。

## 更新链真实性

自 `1.0.0-rc.3` 起，发布方在汇总出 `SHA256SUMS` 后用 Ed25519 发布私钥签出 `SHA256SUMS.sig`，签名覆盖仓库路径、精确 tag 与校验和文件的原始字节。客户端在安装前必须先验签：

- 缺失、重复、超出大小、无法解析或验签失败的 release 一律不安装，并记录跳过原因。
- `v1.0.0-rc.2` 及更早的 tag 保持旧行为（仅比对哈希），旧客户端仍可正常升级。
- 验签依赖内嵌的发布公钥，因此未注入公钥的本地构建不会接受签名 release 的自动更新。

## 发布构建来源

签名清单通过 Go `-overlay` 提供给编译，不再写回 Git 工作树；发布构建强制校验内嵌字节与签名输入逐字节一致，并要求 Go VCS 元数据报告干净来源（无 `vcs.modified=true`、无 `+dirty`）。

## 兼容性

- 公开 beta.3 / RC1 / RC2 客户端可发现 RC3 并按其原有流程升级。
- RC3 起新增的校验和验签只对 `1.0.0-rc.3` 及更高版本生效。
- Linux / macOS 继续使用 tar.gz 安装与手动重开流程。

## 升级步骤

1. 在 XDev 中「检查更新」，或运行 `xdev self update`。
2. Windows 新界面会在下载与校验完成后提供「重启并更新」；准备阶段原程序保持不变。
3. 升级后运行 `xdev version`，应显示 `1.0.0-rc.3`。

## 发布验证

标签 `v1.0.0-rc.3` 指向提交 `cdc2f63ddaa15d06da7740d7f3eb90494d19e178`。标签流水线 run 44931622566 全部 11 个作业成功：三平台构建（含 `go vet ./...`、全量 `go test`、发布契约测试、桌面构建与集成测试）、e2e、清单签名、五平台打包、发布。

公开资产核验结果：

- 共 13 项资产，`SHA256SUMS` 与 `SHA256SUMS.sig` 均已发布。
- `xdev-windows-amd64-v1.0.0-rc.3.exe` 实测 SHA-256 `40f1f7ff4a22db64537cdd12dd954681c2b61b9a2a8376c68e2623f14c53c875`，与 `SHA256SUMS` 对应行一致；ZIP 根成员与裸 EXE 逐字节一致。
- 用发布产物内嵌的公钥验证 `SHA256SUMS.sig`：通过；同一把公钥对"换 tag 重放"和"篡改校验和字节"均拒绝。
- 发布二进制的 Go 版本信息为 `mod v1.0.0-rc.3`、`vcs.revision=cdc2f63`、`vcs.modified=false`，且保留 `.symtab`（未使用 `-s`）。
- 该 EXE 复制到 `%TEMP%` 后 10 秒仍在，而此前同类产物在 2 秒内被删除。

未完成的验证：Windows 实机从 RC2 升级到 RC3 的端到端点击流程、Linux/macOS 实机更新，以及旧客户端（beta.3/RC1/RC2）通过公网实际升级。这些需要真实设备与网络，尚未执行。

另需注意：仓库内 `keys/pub.key` 与标签流水线实际使用的签名公钥不是同一把，因此**用仓库里的公钥文件校验 `SHA256SUMS.sig` 会得到否定的结果**。应以发布二进制内嵌的公钥为准。
