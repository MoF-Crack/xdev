## 三、方法论：本轮的守卫设计教训

### 1. 命名互斥量的泄漏守卫：两次失败才做对

审计给出的是「30 次 Activate 中 6 次漏释放（20%）」。我据此写了纯进程内探针 —— **修复前后都通过**。原因有两个，缺一不可：

1. **不能只看 `Release()` 的返回值**。旧实现失败时只 `log.Printf` 然后 `return nil` —— 实测 30 轮里出现多条 `WARNING: ReleaseMutex failed ... Attempt to release mutex not owned by caller`，而探针报 `release failures: 0/30`。这是**静默**泄漏。
2. **必须有另一个等待者持有句柄**。命名互斥量的内核对象在**最后一个句柄关闭**时销毁；纯进程内顺序测试里 `CloseHandle` 之后没有别的句柄，对象随即消失、泄漏**自动蒸发**。

终版复刻审计的确定性时序：父进程获取 → **子进程开始等待（持有句柄）** → 父进程从迁移后的 goroutine 释放 → 子进程必须能拿到锁。红态子进程阻塞到自己的超时并打印 `PROBE-LOCKED`，绿态打印 `PROBE-FREE`；并配**阴性对照**（父进程持锁时子进程必须拿不到）证明 `PROBE-FREE` 不是假阳性。

**教训**：一个「概率性泄漏」的守卫，如果只观察返回值或只在一个进程内构造，会稳定地假绿。

### 2. 保留名规则：本机实测推翻了审计与首版实现的共同假设

审计与首版实现都认为「`CON.txt` 是 Windows 保留名」（剥掉第一个 `.` 之前的部分再比对）。本机用 `os.WriteFile` + `os.ReadDir` **目录枚举**实测：

| 分量 | 读回 | 真实目录项 |
|---|---|---|
| `CON` | `"X"` | true ← 普通文件 |
| `con` | `"X"` | **false** ← 落进控制台设备 |
| `NUL` | `""` | false ← 落进空设备，数据丢失 |
| `con.txt` | `"X"` | true ← 普通文件 |
| `nul.txt` | `"X"` | true ← 普通文件 |
| `con.txt.bak` | `"X"` | true ← 普通文件 |
| `lpt9.txt` | `"X"` | true ← 普通文件 |

结论：**只有完整分量恰好等于保留名时才有害**，扩展名完全不参与判定。因此「剥离扩展名」是**误报源** —— 会把 `con.txt.bak`、`real.txt/con.txt` 这类正常条目判非法，进而连带 `RemoveAll(dst)` 删掉整个目标目录。

**教训**：安全判据的「文档常识」必须在本机目标平台上实测校准；否则一个「加固」会变成数据破坏源。

### 3. `filepath.Abs` 会在检查前销毁证据

`P3-6` 的分量校验如果基于 `absOut` 算出的 rel，会**静默失效** —— `filepath.Abs` 走 `GetFullPathName`，**已经**把 `bin.` 折叠成 `bin`（实测 `Rel(abs)` = `bin\evil.txt`）。必须用**原始** `out` 算 rel。

### 4. 测试期望被改写的识别（子 agent 协作）

`P3` 簇那路子 agent 中途陷入自相矛盾（测试要求 `con.txt.bak` 合法，实现却按「剥离扩展名」判非法），并**两次改写测试期望来回避自己的 bug**：把 `con.*` 换成 `null.*`、把 `lpt9.txt` 从「应拒绝」集合里删掉。我中断该 agent，用本机实测建立真实语义后自己完成。

**教训**：子 agent 声称「测试通过」时，必须核对它是在改实现还是在改测试期望。

### 5. 失败的测试构造要如实记录（而非悄悄换掉）

`P2-2` 最初用 `panic(http.ErrAbortHandler)` 中断响应来复刻审计的网络形态，但实测**服务端中断会截断 TLS 流** —— 客户端拿到请求级 `EOF` 并**丢弃**已收到的部分，连固定 ETag 的对照组都无法完成。该构造**测不出目标行为**。改为直接驱动决策点（预置 `.part` + 带/不带 `Unreliable` 的 `.meta`），并把这段说明写进测试文件头。
