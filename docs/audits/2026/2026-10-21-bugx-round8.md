## 二、确认缺陷与处置

### P0（2 项，均已修复并复验）

| 编号 | 标题 | 归属 | 状态 |
|---|---|---|---|
| **A-01** | Lua **插件表本身**的读取未受保护 → 宿主 panic（F-10 修复不完整） | plugin | ✅ 修复 + 真实二进制复验 |
| **R8-01** | 前端 `onMounted(async)` 在**卸载之后**才注册监听 → 永久泄漏 + 幽灵 toast | frontend | ✅ 修复 + 变异测试 |

**A-01 详情**：F-10 只把**结果字段读取**包进 `extractField→L.PCall`，但
`L.GetGlobal("PLUGIN")`、`L.GetField(pluginTable,...)` 仍是裸调用；gopher-lua 的
`L.GetField` 会执行 `__index`，而 `ls.Panic` 是 Go panic，直接穿透 `LoadPlugin`。

实测（真实二进制）：
```
panic: …\zzp16.lua:2: p16-boom:install
  github.com/xmdemt/xdev/internal/plugin.promotePluginMethods(...)
      internal/plugin/vfox_compat.go:155
exit code 2
```

**放大点：不需要恶意输入。** 一个普通笔误（`__index` 索引未定义全局、自递归
`__index`）同样打崩宿主。而 `registerUserPlugins` 在 `RegisterAll` 里加载每个用户
插件，即**任意** `$XMDEV_HOME/plugins/*.lua` 都能让 CLI/TUI/GUI **每次启动都崩溃**（DoS）。

修复后同一 PoC：`exit 0`、插件正常注册（`zzp16  P16  system  latest  Lua plugin: zzp16`）、
逐条 `WARNING: getField("install") … treating the field as absent` 可诊断、无 panic。

**几条最值得记录的**：

- **P1-1/P1-2 是同一系统性缺口**：downloader **没有任何一处**校验「组装后的总长度
  == Content-Range 声明的 total」，也没有「新鲜下载不允许收到 206」的检查。三种形态
  都能把**残缺归档**固化进 TOFU 缓存，且 `verifyCacheSidecar` 比对的是同一个坏 pin，
  **永远通过、永不自我修复**（实测连试 3 次都接受同一份 500 字节残缺文件）。用户只能
  手动删缓存。这正好命中票 17 数据线未完成前的**过渡期默认通路**。
- **R8-1 是「谎报成功 + 写坏文件」**：`"# c1"` → `"# c1latest: 2.0\n"`，YAML 里 latest
  键**根本不存在**，而 `refresh` 仍按 `changed=true` 打印 `latest: 旧 -> 新`。
- **R8-2 影响真实语料**：clion/goland/webstorm 的 `2026.2` vs `2026.2.0.1`（数字段相同、
  发布日期不同）—— 全序判「更新」而 `CompareSemver` 判「相等」，latest **永远推不上去**
  且无任何提示。
- **P1-3 让 F-22 的修复目标落空**：`os.Remove` 对非空目录必失败 + `Rename` 无法覆盖，
  `rollbackActivation` 走同一函数同样失败 → 每次重试同一条错误链，`xdev use` 永远修不好。

## 五、结论与 Round 9 建议

**第七轮修复的方向全部正确、加门的地方也守得住**（F-37/F-38/F-43 经实机核对完整且
可移植；F-09/F-52/F-54/F-48/F-50 经复验有效）。但整批偏「窄」——F-04/F-05/F-06/F-39/
F-40/F-44/F-45/F-46 **各只堵了一个调用点或一个按钮**，同一虚假成功/数据丢失仍能经
相邻路径触达；而 F-10/F-22/F-53/F-56 的修复分别留下了 P0/P1 级缺口或回归。

**Round 9 首批建议**（按风险排序）：
1. **A-10** `util.AtomicWriteFile` 改用 `os.CreateTemp` —— 它是**所有调用点的共享底层**
   （config/manifest/discovery/isolator），实测已能跨写者污染内容并造成 557 次并发失败；
   仓库守卫早已把它登记进 `fixedTmpExceptions` 待迁移。
2. **A-11** `withUserPathLock` 可重入化（或显式拒绝嵌套并报错，而非静默降级为无锁）。
3. **A-02** isolator 状态损坏时的容器泄漏（`loadState` 返回 error、`Teardown` 不得静默报成功）。
4. **A-12/A-13/A-14/A-15** env/config 一致性簇（长度校验、CWD 锚点、目录不一致、HMAC 覆盖）。
5. **P2-6** 同 URL 内容变更（建议用 `If-Range`/`ETag` 校验前缀一致性）。
6. **P3-10** 空 `format` 收紧（diff 已给出，且已核实不会让既有断言变红）。
7. **前端 `smoke.mjs` 的断言定位方式**：它靠**源文件字符串匹配**，任何代码搬家都会误报
   （本轮 3 条过时断言正是如此）。建议改为「在 `src/**` 全量源码上搜索」（一行）或退化为
   真正的行为断言。
