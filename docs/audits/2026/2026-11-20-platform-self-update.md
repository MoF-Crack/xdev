## 问题与修复

用户反馈更新界面应自动选择当前设备平台，Windows 下载后不应停留在 ZIP。检查时运行的程序仍为 beta.3，日志有发现 RC1 的记录，没有进入下载阶段的记录。这不能单凭日志断定用户具体点击了哪个按钮，但源码确认弹窗默认列出多个平台的浏览器归档链接；这些链接不会调用应用内的 `ApplyUpdate`。

更新器本身已使用运行程序的 `GOOS/GOARCH` 选择归档并解压安装，本次将平台与归档选择统一为共享的 `SelectedAsset`：GUI 预览、启动进度与实际安装使用相同选择结果。GUI 返回 `platform`、`assetName`，保留的 `downloadUrls` 只含该平台唯一的归档。缺失、重复或下载元数据无效时明确报错，不退回其他平台或安装包格式。这里按运行程序的架构选择，不能把浏览器 user agent 当作平台依据。

弹窗默认显示本机平台、所选更新包与“下载并安装”。主操作调用原有安装接口，执行下载、SHA-256 校验、解压和程序替换；ZIP 只是 Windows 更新的传输格式。浏览器下载放入默认折叠的手动备用区，明确说明仅下载压缩包、不安装、需要自行解压替换。检查结果或候选版本变化时清除旧归档信息，避免错误链接残留。

安装成功仍需关闭并重新打开 XDev，不自动重启。只有后端明确返回 `applied: true` 才显示安装成功；下载结束或进度达到 completed 均不单独代表成功。TLS 验证、应用代理快照、令牌作用域、强制校验和及失败回滚保留。

## 证据边界

浏览器 E2E 使用 Wails 测试 mock；真实 Windows PE 测试验证的是更新器、文件锁与替换流程。两者不能合并表述为原生 GUI 经真实 Wails binding 完成一次安装。正式 RC1 的归档字节经过公开摘要核对，安装测试通过本地可信 HTTPS 服务分发这些字节，不证明任意用户网络均能访问 GitHub CDN。

全量 Go 的一次复验在既有安装器 `TestRemoveLinkEntry_ClearsLegacyRealDirectory` 遇到临时目录重命名拒绝。未改安装器生产代码；该用例独立重复 20 次以及随后完整 Go 复验均通过。本次未运行 Windows race 或 Linux/macOS 真机桌面验收。

本地候选仍报告 `1.0.0-rc.1`，以构建时间、源码提交与 SHA-256 区分，并非替换已发布资产的新版本。既有程序只有升级到包含该修复的构建后才会使用新界面。用户原安装未被自动覆盖；手动下载备用入口与应用内自动安装是不同操作。
