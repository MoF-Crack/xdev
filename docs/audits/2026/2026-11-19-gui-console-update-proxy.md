## 问题与修复

### GUI 启动留下控制台

beta.3 采用同一个控制台可执行文件承载 GUI、CLI、TUI 和工具 shim。双击启动会分配控制台，原 GUI 入口没有释放它；后台残留清理日志又在文件日志初始化前打印，因此用户看到常驻终端中的一条 sweeper 日志。

Windows 桌面 GUI 入口现在先建立文件日志，再调用 `FreeConsole`，只解除当前进程的控制台关联。不隐藏或关闭共享终端窗口，不改变单二进制的 PE 子系统，也不为全部模式增加 `-H windowsgui`。CLI、TUI、shim 路径继续使用其原有标准流；没有桌面运行时的维护构建也保留终端错误输出。

首次设置前的日志也写入当前解析 home 的 `logs/xdev-gui.log`。初始化同一路径不再截断早期日志，切换日志目录时关闭旧句柄，关闭 GUI 后恢复原标准日志输出。标准库日志只通过一个同步 writer，避免同一条记录重复写入。日志初始化和标准日志写入使用一致的锁顺序。

桌面运行时启动失败会写日志，并在 Windows 显示可见错误提示，避免释放控制台后错误消失。配置加载失败发生在控制台释放前，仍能显示原错误。

### 自更新未使用设置页的代理

设置页原来只重配远程嗅探模块的私有客户端，自更新自行建立 HTTP 客户端，因而没有使用应用保存的代理。

自更新现在为每次操作按值捕获代理配置。手动检查、安装前的二次检查、归档下载、`SHA256SUMS`、备用 GitHub 资产 API 共用这次网络快照。GUI 启动更新和 CLI 自更新也使用同一接口。修改设置后，下一次操作采用新配置；在途操作保持原快照，多个 App 之间不共享可变代理客户端。

显式代理使用私有 transport，不修改 `http.DefaultTransport`。`NO_PROXY` 按目标主机、域、IP、CIDR 和可选端口匹配。代理未启用或未填写时保留原来的标准环境代理行为。非法显式代理返回脱敏错误，不静默直连。

TLS 验证、安全重定向、GitHub 令牌作用域、整体时限、校验和、替换与回滚规则保持原有要求。备用下载失败重试仍从头开始，没有新增断点续传；安装成功仍需要用户自行关闭并重新打开程序。

### 验证边界

Windows `go test -race` 因本机 C 编译环境缺少 `stdlib.h`、`windows.h` 等头文件，在 runtime/cgo 编译阶段失败，race 检查没有执行；不能将普通测试通过等同于 race 通过。

原生 GUI 的前两次自动观察使用了 `STARTUPINFO` 的隐藏显示标记，导致 Windows 抑制首个窗口的显示。修正测试启动参数为普通显示模式后四种场景通过；没有为测试失败放宽产品窗口逻辑或更新截图。

本次没有对正在运行的用户程序执行自更新。代理下载验收使用受控可信 HTTPS 和临时目标，不能据此声称任意网络下的 GitHub CDN 都可访问。产品版本仍为 `1.0.0-beta.3`；本地构建通过构建时间、Git 提交和 SHA-256 区分，不能当作新的正式发布。
