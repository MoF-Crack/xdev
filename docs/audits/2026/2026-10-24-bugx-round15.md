## 三、已修复项（TDD，逐项证据）

### R15-1（P2）完整性门禁漏认根部 `.cmd` → android-ndk 装不上

**现象（修复前，纯净 home，真实网络）**

```
$ xdev install android-ndk@latest
[install] Resolved version: latest -> r29
[install] Download complete, starting install-by-kind
[install] ERROR: post-extract integrity check failed for android-ndk at …\install\android-sdk\android-ndk\r29:
          missing binary ndk-build, ndk-stack, ndk-gdb
```

**根因**：NDK r29 的 windows 包（`android-ndk-r29.zip`，833,850,862 字节，sha256 与随包 manifest 一致）根部**只有** `.cmd`：

```
android-ndk-r29/ndk-build.cmd
android-ndk-r29/ndk-gdb.cmd
android-ndk-r29/ndk-stack.cmd
android-ndk-r29/build/ndk-build        ← 无扩展名的那个在这里
```

manifest 是 `strip: 0`，解包后二进制在 `<install>/android-ndk-r29/*.cmd`。而 `binaryCandidates` 只给 `bin/` 与 `<sub>/bin/` 配了 `.cmd`，**根部和「一层子目录根部」都没有** → 一棵完整的安装树被判「不完整」并回滚。这不是 android-ndk 专属：任何只提供 `.cmd`/`.bat` 包装的归档都会中招。

**修复**：`internal/installer/integrity.go` 候选表补 `<install>/<shim>.cmd|.bat` 与 `<install>/<sub>/<shim>.cmd|.bat`。
**守卫**：`internal/installer/integrity_cmd_wrapper_r15_test.go`（真实 NDK 树 / 扁平根部 / 反向守卫「空壳目录仍必须失败」）。
**端到端复验（修复后，同一 home，命中缓存）**

```
[install] Starting install: tool=android-ndk spec=r29
[install] Resolved version: r29 -> r29
[install] Install-by-kind complete (integrity OK)
✔ installed android-ndk@r29 to …\install\android-sdk\android-ndk\r29
✔ activated android-ndk@r29
```

`current/android-ndk → …\r29`，`shims/ndk-build{,.exe}`、`ndk-gdb{,.exe}`、`ndk-stack{,.exe}` 均已生成。

### R15-2（P2）字面版本无法解析 → 默认安装直接失败

**现象（修复前，纯净 home，**无网络请求**即失败）**

```
$ xdev install android-ndk
[install] Starting install: tool=android-ndk spec=r29
[install] ERROR: resolve version failed for android-ndk@r29: unrecognised version spec: "r29"
exit 1
```

**根因**：`install` 不传 `@version` 时把 `p.DefaultVersion()`（manifest 的 `latest` 字面值）当作 **spec** 交给 `resolver.Parse`。semver 形态的字面值刚好也能被 Parse 认成 `KindExact`，所以 52 个工具"刚好"可用；`android-ndk` 的版本名是 `r29`（字母开头）→ Parse 直接报错。53 个随包工具里**这一个是完全装不上的**。
`@r29` 显式写法同样失败（所以不是「默认值」单点问题）。

**修复**：`internal/plugin/generic.go` `Generic.ResolveVersion` 增加**字面兜底**——Parse 失败时，只有当清单里确实存在同名字面版本才放行（顺带兼容两侧 `v` 前缀）；未知字面值仍返回 Parse 原始错误（`resolver_test.go` 的 `TestParseInvalid` 契约不变）。
**守卫**：`internal/plugin/literal_version_r15_test.go`
- `ResolveVersion("r29")` 必须成功且默认版本能自解析；
- 垃圾字面值仍必须被拒；
- **语料驱动**：遍历全部随包 manifest（`len(tools) >= 40` 防空转），逐个断言 `latest`/`lts` 字面值可解析 —— 敏感性命中 `android-ndk: "r29"`。

### R15-3（P2）PowerShell 取值注入（可执行）

**根因**：`psEscape` 把 `"` 转义成 `\"`，但 **PowerShell 的转义字符是反引号**，反斜杠只是普通字符 → 双引号字符串提前结束，后半段成为新语句。

**证据（修复前，真实 `powershell.exe` 5.1）**：取值 `a"; Write-Output R15_INJECTION_MARKER; "b`
生成 `$env:DEMO_HOME = "a\"; Write-Output R15_INJECTION_MARKER; \"b"` → marker 被作为独立语句执行（同一断言在修复前为红，修复后为绿）。

**触发链（真实可达）**：manifest `env_vars` / `xdev plugin install` 拉取的 Lua 插件 `env_vars()` → `xdev env <tool>@<ver> --shell powershell`（文档示例即 `iex "$(xdev env …)"`）→ 用户执行输出 → 任意 PowerShell 落地，绕开 Lua 沙箱。POSIX/fish 分支是单引号包裹，同样输入是惰性的（对照已跑）。

**修复**：`internal/env/env.go` `psEscape` 改为反引号转义 `"`（` `` ` 与 `$` 原本已转义）。
**守卫**：`internal/env/powershell_escape_r15_test.go`（约定级 + 行为级：真的把生成语句交给 `powershell.exe`，要求 marker **不**作为独立输出出现，且取值原样保留）。

### R15-4（P2）PowerShell profile 写进 shell 不加载的孤儿路径

**真实语料（本机）**

```
USERPROFILE                          C:\Users\xinyan
[Environment]::GetFolderPath('MyDocuments')   D:\documents      ← 已重定向
真实 $PROFILE  D:\documents\WindowsPowerShell\Microsoft.PowerShell_profile.ps1   87 B  无 xdev 块
孤儿文件       C:\Users\xinyan\Documents\WindowsPowerShell\Microsoft.PowerShell_profile.ps1  118 B  有 xdev 块
$ xdev doctor --no-path-fix →  ✔ shell rc injected
```

**后果**：`xdev init` / `xdev activate` 报 ✔、`doctor` 报 ✔，但用户 shell **从未**加载 `XMDEV_HOME` 与 cd hook；`self uninstall` 也只会清掉孤儿块。「文档」被 OneDrive / 组策略 / 非英文系统重定向是常见配置。

**修复**：新增 `documentsDir()`（Windows 走 `HKCU\…\User Shell Folders\Personal`，回退 `<USERPROFILE>\Documents`；非 Windows 保持旧推导），`pwshProfile`/`psProfile` 改为基于它。
**守卫**：`internal/env/profile_documents_r15_test.go`（判据 == 系统登记值；profile 必须落在 `documentsDir()` 之下）。
**敏感性已证**：把实现换回 `USERPROFILE\Documents` → 立刻红，报 `documentsDir() = "C:\Users\xinyan\Documents", 但 Windows 登记的「文档」是 "D:\documents"`。

## 四、确认但本轮不修（含「为什么不动」）

| # | 级别 | 结论 | 不修的理由 |
|---|---|---|---|
| 1 | P2 | **`refresh`/嗅探会把 `latest` 推到「无 archives 的发现版本」**。实测 `xdev refresh android-ndk`（隔离 home）把 `latest: "r29"` 改成 `latest: "30"`，而新版条目是 `archives: [] discovered: true unverified: true`；默认安装随后就没有归档可用 | 需要「latest 晋升策略」的产品决策（是「不晋升无归档版本」还是「自动补齐占位归档」），且与 `auto_archive_fill` 的默认值耦合。本轮不猜 |
| 2 | P2 | **android-ndk 的 `ANDROID_NDK_HOME` 少一层**：`strip: 0` 使 NDK 根变成 `<install>/android-ndk-r29/`，而 `ANDROID_NDK_HOME: {{install}}` 指向其父目录（gradle/CMake 会找不到 NDK） | 改 `strip: 1` 会改变整个 android 家族的安装布局与 `current/` 语义，必须连同 6 份 android manifest 一起复验；本轮已让安装跑通，不在同一轮里二次改动 |
| 3 | P2 | **`manifest add/update` 报成功但清单从未生效**：写入 `<ManifestDir>/third-party/`，而 loader 只读 `*.yaml` 顶层；`update` 还丢弃 `WriteFile` 错误并打印 `✔ updated` | 需要决定 third-party 的加载优先级与同名冲突语义（内置 vs 第三方），属设计变更 |
| 4 | P2 | **Windows 中断自愈不可达**：`ApplyTo` 先用 `EvalSymlinks(exePath)`，而崩溃态正是该路径消失 → 自愈分支永远进不去（直接调用 `replaceFromBackup` 可以治） | 修复点在版本替换主流程，需在 Windows 上真实制造「崩溃中途」态复验；本轮时间不足，盲改风险高 |
| 5 | P3 | **`xdev self install` 在 Windows 从 `current\xdev` 调用时失败**（`os.Executable()` 返回 junction 路径，字符串相等守卫失效；`CopyFile` 无 `SameFile` 守卫，目标是被占用的运行镜像） | 同 #4 的文件；Windows 拒绝写入，无数据损坏，只是「修复命令在最常见的调用方式下不可用」 |
| 6 | P2 | **`xdev config set core.xmdevenv_dir` 静默无效**：只改内存字段，`SetRootDir`（A-14 的修复）**零生产调用方**，随后 `Save()` 把「新 home + 旧派生目录」的混合态写盘 | 需要梳理 home 迁移的完整语义（派生目录重锚、旧 home 处置），不是一行接线 |
| 7 | P2 | **`CleanupUserPath` 破坏 UNC / 扩展长度前缀**：把每个 `\\` 折叠成 `\`，`\\server\share` → `\server\share`、`\\?\D:\…` → `\?\D:\…` | 触碰 PATH 写入核心（本机 PATH 是用户全局状态），需要更强的隔离矩阵；本轮只做定性确认 |
| 8 | P2 | **RC 写入非原子 + 悬空 marker 会吃掉用户内容**：`os.WriteFile` 整文件截断；缺结束标记时 `removeBlock` 原样返回，再追加新块 → **下一次**运行会删掉「从首标记到 EOF」的全部用户行 | 与 #7 同属宿主文件写入面；修复需改为 `util.AtomicWriteFile` + 严格配对，并补「悬空标记」用例 |
| 9 | P2 | **前端：Use/Uninstall 后 dashboard 与 favorites 的版本列表陈旧**（只刷新抽屉自己的列表）。表现为「切到 22.0.0 后旧版本仍带 active 标签、点 Remove 后删掉的版本还在列表里」 | 修复面在前端状态编排；子代理已给出可复现的失败用例，但改完需要跑 305 个前端用例回归，本轮时间不足 |
| 10 | P3 | 前端：环境变量级别切换缺请求令牌（可能显示另一级别的变量）；批量更新逐项失败不展示；`Run command` 按空白切分导致带空格参数损坏 | 同 #9 |
| 11 | P2 | **GUI `MigrateLegacyDir` 对任意绝对目录执行「拷贝 + `RemoveAll`」**（只校验不是 symlink、不是 home 内），不校验它**是不是** legacy 目录 | 前端当前只传扫描结果，属纵深防御缺口；触发需要陈旧前端值 |
| 12 | P3 | **macOS launchd 的 `schedule` 未校验就插进 plist XML**（Linux 有 `parseCronSchedule`，macOS/Windows 没有）；可构造第二个 `ProgramArguments` | 本机无法验证 launchd 是否执行；且 Windows 分支参数是数组、无注入面 |
| 13 | P3 | `profile import` 打印「✔ custom tools: restored」，但只写了 `cache/custom_tools.json`（除导出外无人读）；`doctor --fix` 修完仍报 `Some checks failed` / PATH 写失败不改 `allOK` | 前者是 backlog 里未实现的导出/导入；后者需先定义「--fix 的退出码语义」 |

## 七、遗留与建议顺序

1. **#4/#5（自更新/自安装的 Windows 恢复路径）** —— 这两条会让「工具坏了修不回来」，优先级最高。
2. **#1（latest 晋升到无归档版本）** —— 直接导致默认安装失败，且嗅探是自动的。
3. **#2（android 家族的 strip/ANDROID_NDK_HOME）** —— 安装通了但 IDE 集成仍不可用；改前先把 6 份 android manifest 一起复验。
4. **#6/#7/#8（宿主全局状态的写路径）** —— 一旦出错影响整台机器。
5. **#9/#10（前端状态陈旧）** —— 用户可见但无数据损坏。
