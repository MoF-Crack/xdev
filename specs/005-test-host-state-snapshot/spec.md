## Why

Constitution `1.0.0-rc.3` 原则 II 规定：

> "自动化测试不得修改真实用户注册表、用户或系统环境变量、Shell 配置、全局工具目录或其他持久化宿主状态。测试结束后的回滚不能替代隔离。"

当前已知执行缺口第 299 行指出：

> "测试隔离依赖 `--no-path-fix` 等参数，尚缺少统一的宿主状态快照检测。"

当前测试隔离策略依赖各个测试用例自觉遵守隔离约定和 `--no-path-fix` 等参数控制，但缺少统一的自动化检测机制。这意味着：
- 无法客观证明测试确实未修改宿主状态；
- 测试崩溃、超时或被中断时，状态修改无法回滚；
- 新测试可能无意中引入宿主状态修改而未被察觉。

受影响方：
- 所有开发者（宿主状态被测试污染后可能导致本地环境异常）；
- CI 环境（CI runner 的快照状态对后续 job 的影响不可预测）；
- 测试可信度（测试通过不能证明未产生副作用）。

不关闭此缺口：Constitution 的测试隔离要求缺少可验证的执行手段，宿主状态污染的检测完全依赖开发者自律。

## 目标

建立统一的测试宿主状态快照机制：在测试运行前捕获关键宿主状态基线快照，测试运行后比对差异，检测到任何持久化修改时测试标记为失败，并将宿主状态修改视为阻塞性缺陷。

## 范围

### 包含

- 宿主状态快照的采集范围定义（注册表路径、环境变量、文件系统路径、Shell 配置、全局工具目录）
- 测试前后的快照采集和差异比对逻辑
- 差异检测到宿主状态修改时的测试失败信号
- CI 集成（在 CI 中强制执行宿主状态隔离检查）
- 快照机制的跨平台适配（Windows 注册表、Linux/macOS 配置路径）

### 非目标

- 替换现有测试隔离策略（`--no-path-fix` 等参数仍作为第一道防线）
- 对第三方测试框架（如 `testing`、`testify`）的侵入式修改
- 自动修复宿主状态修改
- 在 CI 以外的场景强制执行快照检测
- 快照性能优化（初始实现以正确性为优先）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 自动化测试运行前后宿主状态无差异 (Priority: P1)

开发者或 CI 运行测试套件时，快照机制在测试前后分别采集宿主状态基线。如果测试后宿主状态与测试前完全一致（在定义的检测范围内），快照检测通过，测试正常结束。

**Why this priority**: 这是快照检测的核心价值——自动化验证测试隔离的有效性。

**Independent Test**: 运行已知完全隔离的测试套件，验证快照检测通过且不产生假阳性。

**Acceptance Scenarios**:

1. **Given** 测试套件中所有测试均正确使用临时目录和沙箱，**When** 快照检测在测试后比对宿主状态，**Then** 无差异，快照检测通过
2. **Given** 快照检测通过，**When** 查看测试输出，**Then** 输出中包含 "host state snapshot: no changes detected" 或类似确认信息

---

### User Story 2 - 发现宿主状态变更时测试失败并输出差异 (Priority: P1)

当测试套件中某个测试错误修改了宿主状态（如写入注册表、修改环境变量、在全局目录创建文件），快照检测在测试后发现差异，立即标记测试失败并输出具体的变更内容。

**Why this priority**: 检测到违规时的明确反馈是实现价值的必要条件，与通过场景同等重要。

**Independent Test**: 创建一个故意修改注册表的测试，验证快照检测捕获变更并失败。

**Acceptance Scenarios**:

1. **Given** 测试过程中写入了一个新的注册表键 `HKCU\Software\XDev\test-leak`，**When** 快照检测比对注册表快照，**Then** 检测到差异，测试标记为失败
2. **Given** 快照检测失败，**When** 查看失败输出，**Then** 输出包含：(a) 变更类型（注册表/环境变量/文件系统）；(b) 具体变更路径或键名；(c) 变更前后的值
3. **Given** 测试过程中修改了 `PATH` 环境变量，**When** 快照检测比对环境变量快照，**Then** 检测到差异并输出修改前后的值

---

### User Story 3 - CI 中强制执行宿主状态隔离检查 (Priority: P2)

在 CI pipeline 中，宿主状态快照检测作为测试 job 的一部分或后续验证步骤运行。如果快照检测失败（发现宿主状态被修改），CI job 标记为 failure，阻止包含宿主状态泄漏的代码合并。

**Why this priority**: CI 强制执行是确保隔离持续有效的关键，但依赖本地快照机制先运行正确。

**Independent Test**: 在 CI runner 上运行包含宿主状态泄漏的测试，验证 CI 失败。

**Acceptance Scenarios**:

1. **Given** CI 运行测试 job 且快照检测启用，**When** 检测到宿主状态修改，**Then** CI job 标记为 failure
2. **Given** CI runner 为临时环境且测试完全隔离，**When** 快照检测运行，**Then** CI job 正常通过

---

### 边界条件

- 当测试运行在容器或受限沙箱中（如 CI runner 本身已经隔离）时，快照检测应仍可运行还是跳过？
- 当快照采集本身对宿主状态产生微小影响（如创建临时快照文件）时，如何排除自身干扰？
- 当测试过程中有合法的临时文件创建（如 `%TEMP%` 目录）但测试后已正确清理时，快照比对应如何处理？
- 当不同测试套件并行运行时，快照采集和比对应如何避免竞争条件？

---

## Requirements *(mandatory)*

### 功能需求 (Functional Requirements)

- **FR-001**：测试框架必须支持在测试套件执行前采集宿主状态快照，覆盖范围至少包括：注册表（Windows）、环境变量、指定的文件系统路径和全局工具目录
- **FR-002**：测试框架必须在测试套件执行后重新采集宿主状态快照，并与测试前基线进行差异比对
- **FR-003**：检测到宿主状态差异时，测试必须返回失败并输出：(a) 差异类别；(b) 变更路径或键名；(c) 变更前后的值
- **FR-004**：CI 中的测试 job 必须启用宿主状态快照检测，检测失败时 CI job 标记为 failure
- **FR-005**：快照检测机制必须支持跨平台运行（Windows 注册表 + 文件系统 / Linux + macOS 文件系统 + 环境变量）

### 非功能需求 (Non-Functional Requirements)

- **NFR-001**：性能 — 快照采集和比对的额外耗时不应超过测试总耗时的 5%
- **NFR-002**：安全 — 快照文件不得包含敏感数据（如密钥、密码）；采集时主动过滤已知敏感路径
- **NFR-003**：兼容性 — 快照检测机制不得修改已有测试代码或测试框架的行为
- **NFR-004**：跨平台 — Windows 上采集注册表和文件系统；Linux/macOS 上采集文件系统和环境变量
- **NFR-005**：可维护性 — 快照检测的采集范围必须可配置（允许添加或排除特定路径）

### 关键实体

- **宿主状态快照**：在特定时间点捕获的宿主环境状态集合，包含注册表键值、环境变量键值对、文件系统路径列表和内容 hash
- **差异报告**：测试前后快照比对产生的结构化差异列表，每条差异记录类型、路径、前后值

---

## Success Criteria *(mandatory)*

### 可度量成果

- **SC-001**：创建一个故意修改注册表的测试用例后运行快照检测，测试必须失败并输出注册表变更详情
- **SC-002**：运行完全隔离的测试套件时，快照检测零假阳性通过
- **SC-003**：CI 中启用快照检测后，任何修改宿主状态的测试导致 CI 失败
- **SC-004**：快照采集和比对的额外耗时 ≤ 测试总耗时的 5%

---

## 假设与依赖

- 假设测试使用 Go 标准 `testing` 包或兼容框架（`testify` 等）
- 假设测试运行的操作系统支持程序化访问注册表（Windows）和文件系统
- 假设 CI runner 为干净环境（每次运行状态独立）
- 假设现有 `--no-path-fix` 参数继续作为第一道隔离防线
- 依赖测试框架的 setup/teardown 钩子或 TestMain 机制触发快照采集

## 风险分类

| 风险类别 | 风险描述 | 严重度（高/中/低） | 缓解措施 |
|---|---|---|---|
| 安全 | 快照文件可能捕获敏感信息 | 中 | 采集时排除已知敏感路径；快照文件不进入版本控制 |
| 兼容性 | 快照检测引入的额外文件操作可能与已有测试冲突 | 低 | 快照文件写入临时目录，测试后自动清理 |
| 跨平台 | Windows 注册表 API 在 Linux/macOS 上不可用 | 中 | 平台特定代码分支；非 Windows 平台跳过注册表采集 |
| 持久化 | 快照文件本身可能遗留 | 低 | 使用临时目录并在测试后自动清理 |
| 签名/发布 | 无 | 低 | 不适用 |

## Constitution、兼容性、跨平台与安全影响

### Constitution 影响评估

| Constitution 原则（候选 rc.3） | 影响判定 | 说明 |
|---|---|---|
| 原则 I：安全与信任边界 | Not Applicable | 不涉及信任边界 |
| 原则 II：测试必须隔离宿主状态 | Needs Review | 本 Spec 直接执行该原则——提供统一的宿主状态快照检测 |
| 原则 III：Constitution 与 Spec 是权威约束源 | Compliant | 本 Spec 直接响应 Constitution 识别的执行缺口 |
| 原则 IV：逐任务双重独立审查 | Compliant | 实施时需通过双重审查门禁 |
| 原则 V：Windows 主平台与跨平台分层验证 | Compliant | 快照检测需在 Windows、Linux、macOS 上适配 |
| 原则 VI：向后兼容与可恢复迁移 | Compliant | 不影响已有测试行为，仅增加检测层 |
| 原则 VII：依赖、生成资产与构建必须可复现 | Not Applicable | 不涉及构建可复现性 |

### 兼容性影响

- 是否修改已有 CLI 参数或行为？否（`--no-path-fix` 等参数保持不变）
- 是否修改 manifest 或 lockfile 格式？否
- 是否影响已有目录结构？否
- 是否影响已存在的测试？否（仅新增检测层）

### 跨平台影响

- Windows：采集注册表（`HKCU\Software\`、`HKLM\Software\`）、环境变量、文件系统
- Linux：采集文件系统（`~/.config/`、`/etc/`、`~/.bashrc`）、环境变量
- macOS：采集文件系统（`~/Library/`、`~/.zshrc`）、环境变量
- 平台特定逻辑需通过 build tags 或运行时 OS 检测隔离

### 安全影响

- 是否涉及认证/授权变更？否
- 是否涉及敏感数据存储或传输？是（快照可能捕获文件路径信息；需排除敏感路径）
- 是否引入新的信任边界？否
