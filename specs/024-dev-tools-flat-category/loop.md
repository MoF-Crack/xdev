## 一、批次划分（Batch）

按依赖关系分组，同一 Batch 内可并行（分派不同 subagent 时注意写冲突），批次间串行。

| Batch | Tasks | 内容 | 依赖 | 并行性 |
|-------|-------|------|------|--------|
| B1 | T-A1, T-A2 | 归并层（gui）+ 并行加载（manifest） | 无 | 文件不重叠，可并行 |
| B2 | T-B1, T-B2, T-B3 | manifest 迁移 + i18n + 测试 fixture | B1（T-A1 归并层） | 三者文件不重叠可并行；都依赖 B1 完成 |
| B3 | T-C1, T-C2, T-C3 | 集成验证 + 手动场景 + 文档 | B1-B2 全部 | 串行收尾 |

> **范围调整（2026-08-04）**：原 B3「前端并行预取」已移除（避免 N 倍 RPC 负载与前端 cache 一致性复杂度）。原 B4 集成验证上移为 B3。

## 二、每批 LOOP 流程（Implement → Verify → Review → 收敛）

```
┌─ LOOP 入口（Batch N）
│
├─ L1 Implement：分派 subagent 实施（fixer，见「分派策略」）
│     · 小步执行：每文件改完即编译检查
│     · 明确边界：只做本 Batch 内容，不越界重构
│     · 超时护栏：单任务 >15 分钟无进展 → 中断并检查半成品
│     · 若模糊则最小合理决策并继续，禁止停滞
│
├─ L2 Verify（自动验证门，必须全绿才进 Review）
│     · go build ./...（编译）
│     · 目标测试：go test <涉及包> -short（该 Batch 全部新增/关联测试）
│     · 前端（B3/B4）：npx vite build + 相关 vitest
│     · L2 失败 → 回退到 L1 修复（修复循环，见四）
│
├─ L3 Review（独立审查门）
│     · 必审 Batch：B1（后端能力地基）、B2（manifest 正确性）
│     · 审查人：oracle（Go 改动）；observer/人工对前端
│     · 审查项：行为一致性、向后兼容、测试覆盖、无越界改动
│     · L3 发现问题 → 回退到 L1 修复
│
└─ L4 收敛：Batch 全部通过 → 更新 checklist 勾选 + 进入下一 Batch
        直至 B4 完成 → 全量收敛（见五）
```

## 三、分派策略

| Batch | 主实施 | 理由 |
|-------|--------|------|
| B1 | fix-1（后端 A1 归并层）+ fix-2（后端 A2 并行加载） | A1 在 gui 包，A2 在 manifest 包，文件不重叠可两个 fixer 并行 |
| B2 | fix-1（manifest 批量 B1）+ fix-2（i18n B2）+ 我（测试 fixture 排查 B3） | manifest 批量编辑脚本化；i18n 小改；fixture 需排查决策 |
| B3 | 我（全量验证 + 手动场景 + 文档） | 集成收尾 |

**防挂起护栏**（历史教训：Spec 023 mingw.yaml 重复 key 事故）：
- 每个 subagent 任务给出明确"若模糊则最小合理决策并继续，禁止停滞"
- 只跑目标测试，不跑全量（B4 才全量）
- 我实时监控：任务 >15 分钟无结果 → 查询状态；若卡死 → 中断并检查半成品文件，修复后继续或换策略
- manifest 批量编辑用脚本+校验（重复 key 扫描 + yaml 解析测试），避免手工破坏
- 前端任务给出明确的 API 契约（后端归并层已定型），避免前端猜测后端语义

## 四、修复循环（L2/L3 失败回退）

```
L2/L3 发现失败
  ├─ 记录问题（文件/测试/错误）
  ├─ 判断：
  │    ├─ 半成品（subagent 中断遗留）→ 我检查并修复残留（如重复 key/坏缩进）→ 重跑验证
  │    ├─ 单点缺陷 → 回退 L1 修复该点 → 重跑 L2（≤3 次）
  │    └─ 设计缺陷（>3 次或跨多点）→ 停止，报用户讨论（架构问题不硬修）
  └─ 修复后重跑：L2 全绿 → L3 → 收敛
```

**收敛定义（单 Batch）**：目标测试全通过 + build 通过 + 审查无阻塞项。

## 六、风险与护栏汇总

| 风险 | 护栏 |
|------|------|
| subagent 卡死/挂起 | 15 分钟超时查询 + 中断 + 半成品检查修复 |
| manifest 批量编辑破坏（重复 key/坏缩进） | 脚本化编辑 + 重复 key 扫描 + 每批 manifest 解析测试 |
| 前后端接口不同步 | B1 后端先完成并测试，B2 依赖 API 定型后才动 |
| 并行加载改变错误语义 | A2 保持"返回第一个错误"；测试覆盖单文件损坏 |
| 归并层漏掉旧 category | 归并映射显式列举；测试覆盖每种旧 category |
| 磁盘 manifest 副本残留旧 category | F2 归并层兜底；B1 同步 `E:\XDev\manifests\` |
| e2e fixture 引用旧分类名 | B3 同步更新；B3 验证 |
