# 签名密钥生成与恢复

`xdev keygen --pub-key <新公钥路径> --priv-key <新私钥路径>` 只允许生成到两个此前不存在的不同文件。Windows 在 `CREATE_NEW` 时提供仅当前用户的受保护 DACL；Unix 独占创建模式为 `0600`。占用、别名、已存在输出都是错误，不会轮换已有密钥。两个文件可在不同目录，此操作**不是**跨目录原子事务。正常错误回收本次创建的文件；进程被强杀/掉电可能留下其中一个新文件。

**轮换**：先保管旧私钥、对应公钥、旧签名清单及原发布二进制（私钥离线受限存储，不能随发布件提交）。在新目录生成新 pair；检查公钥确为32字节，并用同一私钥签名、对应公钥验证，再把新根、匹配的清单签名与二进制作为同批发布。不能仅换公钥文件便假定旧二进制会信任新根。CI release 步骤的 `go run ./internal/signer/checkpair` 要求 `XDEV_SIGNING_{PUBLIC,PRIVATE}_KEY` 为匹配且内部一致的 canonical base64 Ed25519 pair。

**恢复**：发布前失败，仅清理经过身份核对、确定属于本次尝试的新输出；不能删除旧文件来绕过独占创建。发布后需回退时，从受限备份恢复**同一批**旧签名私钥、旧公开根、旧签名目录和绑定旧根的发布构建；先在隔离环境验证旧签名再重新发布。不要用临时新生成私钥代替丢失的旧根。若旧私钥已泄露，回退并不恢复其可信性，需要独立可信渠道更新二进制和根。

未嵌入根（空字符串）的开发构建继续支持无签名兼容路径；非空错误编码、占位字符串和长度异常都不等于“未配置”。调用方应传播 `RootPublicKeyChecked` 的错误。验签之外，已配置的真实 ExpectedSHA 比较仍应执行。
